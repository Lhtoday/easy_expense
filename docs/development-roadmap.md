# ExpenseFlow 开发路线图

这份文档定义费用报销项目的推荐开发顺序。原则是先打牢业务闭环和数据一致性，再逐步增强财务自动化、票据智能化和外部系统集成。

## Phase 0：项目基础

目标：先让前后端、数据库、测试和部署骨架跑起来。

1. 初始化 `frontend`：React + TypeScript + Vite + Ant Design
2. 初始化 `backend`：NestJS + TypeScript + Prisma
3. 配置 PostgreSQL、Redis、MinIO 的 Docker Compose
4. 建立基础环境变量、日志、错误处理和健康检查
5. 建立前后端 lint、format、test 脚本
6. 建立 API 响应格式、分页格式和错误码约定

交付标准：

- 前端可以启动并访问基础页面
- 后端可以启动并连接数据库
- Prisma migration 可以正常执行
- Docker Compose 可以启动核心依赖

## Phase 1：身份权限与基础主数据

目标：建立费用系统的组织、权限和基础数据底座。

1. 用户管理
2. 角色管理
3. 部门管理
4. 成本中心管理
5. 项目管理
6. 基础权限模型
7. 登录、当前用户、菜单权限和数据权限雏形
8. 权限清单页
9. 角色权限展示与弹窗式批量勾选维护

交付标准：

- 用户可以登录
- 不同角色看到不同菜单和数据范围
- 系统管理员可以查看全部权限编码、名称和状态
- 角色可以通过权限弹窗维护授权范围，并支持全部勾选
- 报销单后续能关联部门、成本中心和项目

## Phase 2：报销单核心

目标：完成报销单从草稿到提交的核心能力。

1. 报销单主表
2. 报销明细表
3. 报销单编号规则
4. 草稿保存
5. 明细行新增、编辑、删除
6. 金额合计、税额合计、可报销金额合计
7. 提交前基础校验
8. 报销单列表、详情、编辑页

交付标准：

- 员工可以创建、编辑、保存和提交报销单
- 报销单状态机开始生效
- 金额字段不使用浮点数直接计算

## Phase 3：附件与发票元数据

目标：让报销单具备票据和附件支撑，但先不做复杂 OCR。

1. MinIO 文件上传
2. 附件元数据表
3. 报销单附件关联
4. 发票元数据表
5. 手动录入发票代码、号码、金额、税额、开票日期、销方信息
6. 发票重复校验
7. 附件预览和下载鉴权

交付标准：

- 报销单可以上传附件
- 报销明细可以关联发票
- 重复发票会被识别和拦截或提示

## Phase 4：轻量审批流

目标：完成 MVP 阶段的审批闭环。

1. 审批实例表
2. 审批任务表
3. 审批日志表
4. 基础审批流配置
5. 提交后创建审批实例
6. 主管审批
7. 通过、驳回、撤回
8. 审批记录展示
9. 待办、已办、我发起的列表

交付标准：

- 报销单可以进入审批
- 审批人可以处理任务
- 驳回后员工可以修改再提交
- 所有审批动作都有日志

## Phase 5：费用政策控制

目标：把费用制度从人工判断转成系统规则提示。

1. 费用类型管理
2. 费用政策表
3. 政策规则表
4. 单笔金额限制
5. 职级、城市、费用类型限制
6. 是否必须发票
7. 是否必须事前申请
8. 超标提醒、禁止提交、升级审批

交付标准：

- 提交报销时能自动检查费用政策
- 超标报销有明确提示
- 政策结果能影响审批路径或财务审核重点

## Phase 6：预算控制

目标：建立报销与预算之间的约束关系。

1. 预算表
2. 预算占用表
3. 按部门、成本中心、项目、费用科目的预算维度
4. 提交时占用预算
5. 驳回、撤回、作废时释放预算
6. 审批通过后确认占用
7. 付款后转为实际发生
8. 超预算预警或拦截

交付标准：

- 报销单提交会影响预算可用额
- 单据状态变化会正确释放或确认预算
- 并发提交不会导致预算错误

## Phase 7：财务审核

目标：把业务审批和财务审核拆开，形成财务专业控制点。

1. 财务审核工作台
2. 会计科目选择
3. 税额和可抵扣税额确认
4. 成本中心、项目、辅助核算确认
5. 发票异常复核
6. 费用归属调整
7. 财务通过、退回补充、拒绝

交付标准：

- 业务审批通过后进入财务审核
- 财务可以调整会计处理维度
- 财务审核结果进入审计日志

## Phase 8：出纳付款

目标：完成从报销审批到付款登记的闭环。

1. 付款记录表
2. 付款批次表
3. 待付款列表
4. 付款登记
5. 付款失败、重新付款、部分付款预留
6. 付款凭证附件
7. 出纳权限控制

交付标准：

- 财务审核通过的报销单可以进入待付款
- 出纳可以登记付款
- 报销单可以流转到已付款状态

## Phase 9：凭证草稿

目标：生成会计凭证草稿，先不直接过账。

1. 会计科目表
2. 费用类型与科目映射
3. 员工往来科目映射
4. 凭证主表
5. 凭证明细表
6. 报销确认凭证草稿
7. 付款凭证草稿
8. 凭证预览和财务确认

交付标准：

- 系统可以根据报销单生成凭证草稿
- 财务可以查看和确认凭证明细
- 凭证生成过程可追溯

## Phase 10：审计、报表与看板

目标：让财务管理者和审计人员能看清数据。

1. 审计日志查询
2. 部门费用报表
3. 项目费用报表
4. 成本中心费用报表
5. 预算执行率
6. 审批耗时分析
7. 超标报销分析
8. 发票异常分析

交付标准：

- 管理者可以看到费用趋势和预算执行情况
- 审计人员可以追踪关键操作链路

## Phase 11：智能化与外部集成

目标：在核心系统稳定后，再做智能化和外部系统对接。

1. OCR 发票识别
2. 发票验真接口
3. 风险评分
4. 智能科目推荐
5. 企业微信、钉钉或飞书通知
6. ERP 或总账系统对接
7. 银企直连或付款接口
8. HR 系统人员组织同步

交付标准：

- 智能能力不破坏原有人工审核流程
- 外部接口具备签名校验、幂等和失败补偿

## 推荐 MVP 边界

第一版 MVP 建议做到 Phase 0 到 Phase 8。

也就是先完成：

- 基础组织和权限
- 报销单提交
- 附件和发票元数据
- 基础审批
- 费用政策
- 预算占用
- 财务审核
- 付款登记

凭证草稿、报表、OCR、验真、风险评分和系统对接可以作为第二阶段。
