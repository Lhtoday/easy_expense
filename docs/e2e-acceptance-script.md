# ExpenseFlow 端到端验收剧本

本文档用于人工验收、演示准备和 AI 回归检查。验收优先级为：财务合规细节第一，核心流程跑通第二。

## 验收目标

- 验证管理员能准备组织、权限、费用政策和预算前置数据。
- 验证员工、主管、财务审核、出纳四类角色能完成报销闭环。
- 验证金额、税额、发票、预算、状态流转、权限和审计日志符合财务系统要求。
- 验证异常分支不会绕过财务审核、付款前置条件或预算释放规则。

## 角色与账号

以 `docs/startup-guide.md` 中的默认登录信息为准。若本地测试数据不同，验收前记录实际账号和角色映射。

- 系统管理员：维护用户、角色、权限和基础主数据。
- 员工：创建、编辑、提交和撤回自己的报销单。
- 主管审批人：处理业务审批任务。
- 财务审核人：复核会计维度、税额、发票、预算和政策结果。
- 出纳：登记成功付款或失败付款。

## 前置场景 A：管理员配置组织与权限

1. 使用系统管理员登录。
2. 确认至少存在一个部门、一个成本中心、一个项目。
3. 确认员工已关联部门和成本中心。
4. 确认主管审批人拥有 `exp:approval:read` 和 `exp:approval:approve`。
5. 确认财务审核人拥有 `exp:finance-review:read` 和 `exp:finance-review:review`。
6. 确认出纳拥有 `exp:payment:read` 和 `exp:payment:pay`。

验收点：

- 不同角色登录后只能看到自己有读取权限的菜单。
- 高风险动作不能只依赖普通管理员权限，应由独立权限控制。
- 用户、角色和权限变更应保留可追溯记录或至少能通过当前权限配置复核。

## 前置场景 B：管理员配置费用政策

1. 进入费用政策管理。
2. 确认费用类型包含差旅费、交通费、招待费、办公费或其他必要类型。
3. 确认至少一条必须发票规则启用。
4. 确认至少一条单笔金额限制规则启用。
5. 确认规则动作区分提醒、禁止提交和升级审批。

验收点：

- 必须发票规则命中时，关联发票价税合计小于明细金额应阻止提交。
- 单笔限额按费用金额校验，不按可报销金额规避控制。
- 政策检查结果应展示在报销单详情中，供审批和财务复核查看。

## 前置场景 C：管理员配置预算

1. 进入预算控制。
2. 创建或确认一个有效预算，维度至少覆盖部门、成本中心、费用类型和会计科目中的关键字段。
3. 设置预算总额、币种、预警阈值和控制模式。
4. 保留一个足额预算场景和一个超预算预警或阻断场景。

验收点：

- 预算金额使用最小货币单位或定点数，不应出现浮点误差。
- 预算区分在途、已审批、实际发生和已释放金额。
- 预算调整或修复类动作应写入预算操作日志。

## 主流程：报销到付款闭环

### 1. 员工创建并提交报销单

1. 员工登录。
2. 新建报销单，填写标题、部门、成本中心、项目和币种。
3. 添加至少一条报销明细，填写发生日期、费用类型、会计科目、金额、税额、可抵扣税额和可报销金额。
4. 上传附件。
5. 登记并关联发票，填写发票代码、号码、开票日期、销方、购方、金额、税额、可抵扣税额和价税合计。
6. 保存草稿后再提交。

验收点：

- 金额、发票金额、税额、可抵扣税额、可报销金额和已付金额应分字段展示。
- 提交后状态从 `DRAFT` 进入 `SUBMITTED`。
- 提交动作写入报销单状态日志。
- 提交时生成政策检查和预算占用结果。
- 提交时预算进入在途占用，不应直接进入实际发生。

### 2. 主管处理业务审批

1. 主管审批人登录。
2. 进入审批任务，筛选待办。
3. 打开报销单详情，查看金额、政策命中、预算影响、发票状态和历史意见。
4. 对合规单据执行通过。

验收点：

- 审批任务从待办变为已办。
- 审批通过后报销单进入 `BUSINESS_APPROVED`，而不是直接付款或直接完成。
- 审批动作写入审批日志，包含操作者、动作、时间、意见、前状态和后状态。
- 业务审批不得替代财务审核。

### 3. 财务审核复核并通过

1. 财务审核人登录。
2. 进入财务审核工作台，筛选 `BUSINESS_APPROVED` 单据。
3. 打开详情，复核会计科目、成本中心、项目、税额、可抵扣税额、发票关联、重复发票、发票金额覆盖和预算影响。
4. 如明细缺少会计维度或税额不一致，先执行财务修正并记录意见。
5. 对无 BLOCK 问题的单据执行财务审核通过。

验收点：

- BLOCK 级复核问题存在时不能通过财务审核。
- 财务修正写入财务审核记录和报销单状态日志。
- 财务审核通过后报销单进入 `FINANCE_APPROVED`。
- 财务审核通过后预算从在途或待确认状态转为已审批占用。
- 财务审核动作独立于业务审批记录，便于审计追溯。

### 4. 出纳登记付款

1. 出纳登录。
2. 进入出纳付款工作台，筛选 `FINANCE_APPROVED` 单据。
3. 打开待付款详情，核对可付金额、收付款账号、付款方式和付款日期。
4. 登记成功付款。

验收点：

- 只有 `FINANCE_APPROVED` 单据可以成功付款。
- MVP 阶段成功付款必须覆盖剩余可付金额。
- 成功付款后报销单进入 `PAID`，并更新 `paidAmountCents`。
- 付款记录和付款批次可在详情中查看。
- 付款动作写入付款审计记录和报销单状态日志。
- 已审批预算占用转为实际发生金额。

### 5. 查看日志和归档信息

1. 回到报销单详情。
2. 查看报销单状态日志、审批记录、财务审核记录、预算检查/占用记录和付款记录。
3. 核对每个核心动作的操作者、时间、动作、前状态、后状态和意见。

验收点：

- 审计链路能解释单据从创建到付款的完整过程。
- 附件预览和下载需通过鉴权接口，不应暴露永久公开链接。
- 财务审核、付款、预算变化均能追溯到具体人员和业务单据。

## 异常分支

### A. 员工撤回

- 在主管尚未处理前撤回已提交单据。
- 验收：状态回到 `DRAFT`，审批待办关闭，预算在途占用释放，撤回写入状态日志。

### B. 主管驳回

- 主管驳回单据。
- 验收：报销单进入 `REJECTED` 或可修改状态，审批日志完整，预算占用释放。

### C. 财务退回补充或拒绝

- 财务对 `BUSINESS_APPROVED` 单据执行退回补充或拒绝。
- 验收：财务审核记录完整，报销单状态正确变化，预算占用释放，不允许继续付款。

### D. 付款失败

- 出纳登记付款失败。
- 验收：付款失败记录可查，报销单保持 `FINANCE_APPROVED`，允许重试，失败原因写入审计信息。

### E. 重复发票

- 登记一张与历史记录重复的发票。
- 验收：重复状态可见；如属于阻断规则，提交或财务审核不得通过。

### F. 超预算

- 提交一张触发预算预警或阻断的报销单。
- 验收：预警模式允许继续但有提示；阻断模式不允许绕过；预算检查结果可追溯。

## Phase 9 凭证草稿收尾验收

1. 使用具备 `gl:account:read`、`gl:account:write`、`gl:voucher:read`、`gl:voucher:generate`、`gl:voucher:confirm` 权限的财务账号登录。
2. 确认会计科目和科目映射已准备，可执行 `scripts/seed-phase9-accounts.sql` 或在“会计设置”中维护。
3. 打开已付款的 `PAID` 报销单，执行凭证预览，确认费用确认凭证和付款核销凭证借贷平衡。
4. 生成凭证草稿，确认报销单进入 `VOUCHER_DRAFTED`，凭证列表显示 `DRAFT`，凭证展开区可看到 `GENERATE` 日志。
5. 在未确认前执行“撤销草稿”，填写撤销原因，确认报销单回到 `PAID`，原草稿变为 `VOIDED`，并可重新生成新草稿。
6. 再次生成草稿并确认全部凭证，确认报销单进入 `VOUCHER_CONFIRMED`，凭证展开区可看到 `CONFIRM` 日志。
7. 对已确认凭证尝试撤销草稿，应被清晰阻断，提示需走后续冲销或作废流程。
8. 对缺少费用类型、员工往来、进项税或付款方式映射的场景执行预览/生成，应返回可定位的错误提示。

验收点：

- 重复生成活跃凭证会被阻断；撤销未确认草稿后允许重新生成。
- 撤销草稿不改变付款记录、不回滚预算实际发生，仅把凭证草稿状态和报销单凭证状态回退。
- 凭证生成、确认、撤销均可在凭证领域日志、报销单状态日志和系统审计日志中追溯到操作者、时间、前后状态和意见。
